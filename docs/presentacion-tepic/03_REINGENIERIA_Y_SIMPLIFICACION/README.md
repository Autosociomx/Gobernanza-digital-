# 03 — REINGENIERÍA Y SIMPLIFICACIÓN

## Ficha estándar

| Campo | Respuesta |
|---|---|
| **Problema** | El proceso actual (AS-IS) implica visitas presenciales, documentos físicos redundantes, tiempos de espera y sin trazabilidad |
| **Afectados** | Ciudadanos y funcionarios municipales que operan el trámite |
| **Obligación/Necesidad** | LNETB Art. 34 (principios de simplificación): mínima intervención, proporcionalidad, no duplicidad, digitalización integral |
| **Propuesta** | Rediseñar el proceso eliminando requisitos redundantes, digitalizando cada paso y conectando fuentes de datos municipales |
| **Evidencia** | Mapa AS-IS documentado. Prototipo TO-BE funcional. Matriz de eliminación de requisitos con fundamento jurídico |
| **Brecha** | Los datos reales del proceso actual deben ser proporcionados por el Ayuntamiento. Las metas de reducción son proyecciones |
| **Responsable** | Ayuntamiento (datos reales) + proponente (metodología y prototipo) |
| **Fundamento** | LNETB Arts. 19, 34, 66, 68 |
| **Estado** | 🟡 Preparado — metodología lista, datos reales del trámite pendientes |
| **Evidencia física** | `demo/constancia-residencia/index.html`, `03_REINGENIERIA/PROCESO_TO_BE_PROPUESTO.md` |

## Contenido

| Archivo | Contenido |
|---|---|
| `PROCESO_AS_IS.md` | Mapa del proceso actual con estimaciones (por verificar con Ayuntamiento) |
| `PROCESO_TO_BE_PROPUESTO.md` | Flujo digital propuesto: 0 visitas, 0 copias, <10 minutos |
| `MATRIZ_REQUISITO_POR_REQUISITO.md` | Cada requisito actual → fundamento → eliminable → sustitución |
| `MATRIZ_DATOS_Y_DOCUMENTOS.md` | Datos recabados, minimización, protección |
| `ANALISIS_DE_CARGAS.md` | Cálculo de reducción proyectada (visitas, tiempo, costo, documentos) |
| `INDICADORES_PROPUESTOS.md` | KPIs con línea base por determinar y metas |
